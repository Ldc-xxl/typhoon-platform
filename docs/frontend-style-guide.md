## 一、目录与文件职责

```
src/main/webapp/                  ← 前端根目录（部署后即 Web 根）
├── *.html                        10 个页面，只有结构骨架，不含业务代码
│                                 页面内不写 <script> 逻辑，也不写行内 style
├── css/
│   ├── tokens.css                第 1 层：设计令牌（颜色/字号/间距/圆角/阴影）
│   ├── app.css                   第 2 层：全站通用组件与布局系统
│   └── pages.css                 第 3 层：页面级 / 单页专用样式
├── js/
│   ├── data.js                   数据层：模拟数据（ZFZ.mock）
│   ├── api.js                    接口层：RESTful 契约（ZFZ.api）
│   ├── ui.js                     渲染层：无状态的 HTML 片段工厂（ZFZ.ui）
│   ├── layout.js                 骨架层：顶栏/导航/页头/页脚（ZFZ.layout）
│   └── pages/*.js                页面层：每页一个模块，只做"取数 + 拼装 + 绑事件"
├── assets/svg/                   静态矢量资源（地图底图、Logo）
└── vendor/                       第三方库本地副本（jQuery / Bootstrap）
```

### 引用顺序（不可调换）

```html
<link rel="stylesheet" href="vendor/bootstrap.min.css">
<link rel="stylesheet" href="css/tokens.css">      <!-- 必须先于 app.css -->
<link rel="stylesheet" href="css/app.css">         <!-- 必须先于 pages.css -->
<link rel="stylesheet" href="css/pages.css">

<script src="vendor/jquery.min.js"></script>
<script src="vendor/bootstrap.bundle.min.js"></script>
<script src="js/data.js"></script>                 <!-- 数据 -->
<script src="js/api.js"></script>                  <!-- 接口 -->
<script src="js/ui.js"></script>                   <!-- 渲染原语 -->
<script src="js/layout.js"></script>               <!-- 骨架 -->
<script src="js/pages/xx.js"></script>             <!-- 本页逻辑，最后 -->
```

## 二、CSS 命名规则

### 2.1 采用的 BEM 变体

标准 BEM 写作 `block__element--modifier`。本项目采用**业界常见的 BEM 变体**：
元素用**单个连字符**连接，修饰符统一用 `is-` 前缀，理由是
`.trow` / `.panel-head` 这类写法在长类名组合下可读性更好、也不与 Bootstrap 冲突。

| BEM 角色 | 本项目写法 | 示例 |
|---|---|---|
| Block（块） | `.名词` | `.panel`、`.tbl`、`.trow`、`.ty-item`、`.zbtn` |
| Element（元素） | `.块-元素` | `.panel-head`、`.panel-title`、`.zbar-fill`、`.cell-link` |
| Modifier（修饰符） | `.is-状态` | `.is-active`、`.is-narrow`、`.is-open`、`.is-danger` |
| 局部作用域块 | `.父前缀-子块` | `.drop-item`、`.dh-name`、`.ai-tile`、`.casualty-loss` |

**若答辩时老师严格要求 `__` / `--` 写法**，可做一次机械替换
（`panel-head → panel__head`、`is-active → panel--active`），需同步改 4 个 CSS
与 16 个 JS 文件，**属于组织层改动，不影响视觉与功能**。

### 2.2 命名硬性约定

| 规则 | 说明 |
|---|---|
| 全小写 + 连字符 | 不使用驼峰、下划线、大写字母 |
| 语义化，不用表现命名 | 用 `.panel-title` 而非 `.blue-bold-text` |
| 状态类一律 `is-` 开头 | `.is-hidden` / `.is-playing` / `.is-cleared` |
| 单页专用样式放 pages.css | 且以页面前缀收口，如 `.sandbox-*`、`.casualty-*` |
| 不使用 `!important` | 靠层级与选择器权重解决，全站 0 处使用 |
| 不使用 id 选择器写样式 | id 只用于 JS 取元素（如 `#btn-snapshot`） |
| 禁止行内 `style` 写静态样式 | 仅允许 JS 写入**运行时计算值**（如 `width:40%`、`transform`） |

### 2.3 与 Bootstrap 5 的类名避让（**重要**）

Bootstrap 已占用 `.card` / `.btn` / `.nav-item` / `.progress` / `.col` 等类名，
直接复用会被 Bootstrap 样式污染。本项目的避让方案：

| 我们用的类 | Bootstrap 同名类 | 避让原因 |
|---|---|---|
| `.panel` | `.card` | `.card` 自带边框/圆角/内边距，与设计稿不符 |
| `.zbtn` | `.btn` | `.btn` 自带高度/字体/内边距 |
| `.navlink` | `.nav-item` | 仅复用 `.nav` 布局，条目样式全部自写 |
| `.zbar` | `.progress` | `.progress` 自带 16px 高与背景条 |
| `.colstack` | `.col` | `.col` 依赖 `.row` 的负边距栅格，本项目用 Flex |

> 新增组件时**先确认类名是否被 Bootstrap 占用**（`vendor/bootstrap.min.css` 里搜一下），
> 占用就换名或加前缀。

### 2.4 设计令牌优先

颜色、字号、间距、圆角、阴影**一律取自 `tokens.css` 的 CSS 变量**，不写裸值：

```css
/* ✅ 正确 */
.panel-title { color: var(--ink); font-size: var(--fs-body); }

/* ❌ 禁止 */
.panel-title { color: #152A3D; font-size: 14px; }
```

主要令牌：

| 类别 | 令牌 | 值 |
|---|---|---|
| 品牌色 | `--brand` / `--brand-light` | `#0E5484` / … |
| 正文 | `--ink` / `--ink-2` / `--ink-3` | `#152A3D` / `#5B6B7B` / `#93A1B0` |
| 背景 | `--bg` / `--card` / `--row-alt` | `#F2F5F8` / `#FFFFFF` / `#F7F9FB` |
| 描边 | `--line` / `--divider` | `#E4E9EF` / `#D8E0E8` |
| 地图 | `--map-frame` | `#0E3B59` |
| 语义 | `--ok` / `--warn` / `--risk` | 绿 / 橙 / 红 |
| 圆角 | `--r-card` / `--r-inner` | 卡片 / 内部控制 |
| 间距 | `--gap-card` / `--pad-head` | 卡片间距 / 表头内边距 |
| 字重 | `--fw-medium` / `--fw-bold` | `500` / `700` |

> 例外：地图 SVG 内部的高程带、云絮渐变等**图形专用色**直接写在 SVG 里，
> 因为它们是画面内容而不是界面主题。

## 三、布局约定

### 3.1 页面骨架

```html
<div class="app">
  <header class="app-header">…</header>       <!-- 高 60px，由 layout.js 注入 -->
  <nav class="main-nav">…</nav>               <!-- 主导航，由 layout.js 注入 -->
  <main class="page-body">                    <!-- 内容区 -->
    <div class="page-title-bar">…</div>       <!-- 页标题条 -->
    <div class="colstack col-left">…</div>    <!-- 左列 -->
    <div class="colstack col-map">…</div>     <!-- 主列 -->
  </main>
</div>
```

### 3.2 列宽与自适应

| 类 | 宽度 | 用于 |
|---|---|---|
| `.col-left` | 264px | 左列（台风列表） |
| `.col-map` / `.col-main` | `flex: 1` | 主内容列，自适应 |
| `.col-side` | 340px（`.is-narrow` 320 / `.is-wide` 360） | 右侧信息列 |

- **设计基准宽度 1440px**，主内容列随窗口伸展；
- 列容器统一用 `.colstack`（纵向 Flex + `--gap-card` 间距）；

### 3.3 「替换元素不得只给 `inset: 0`」约定

地图等叠放图层必须**显式给出宽高**，否则 `<img>` 会退回固有尺寸、
与旁边按宽度缩放的 SVG 错位：

```css
.map-canvas { position: relative; aspect-ratio: 804 / 462; }   /* 锁定原始比例 */
.map-layer  { position: absolute; inset: 0; width: 100%; height: 100%; }
.map-canvas > img.map-layer { object-fit: cover; }             /* 与 SVG 的 slice 同语义 */
```

### 3.4 交互反馈四态

任何可点击元素必须给全 `cursor` / `:hover` / `:active` / `:focus-visible`：

```css
.zbtn { cursor: pointer; }
.zbtn:hover { background: #E8EEF4; }
.zbtn:active { transform: translateY(1px); }
.zbtn:focus-visible { outline: 2px solid var(--brand-light); outline-offset: 1px; }
```

### 3.5 弹层：挂 body、类名 `.zdlg`、层级低于 toast

管理后台的「编辑用户」是全站第一个浮层组件（`.zdlg` / `.zdlg-mask`），约定如下：

- **类名用 `.zdlg` 而不是 `.modal`**：Bootstrap 自带 `.modal` 的 `display`/`position`
  规则，占用同名类会被它牵着走（与 `.panel` / `.zbtn` / `.navlink` 同一避让原则）。
- **必须挂在 `<body>` 末尾，不能放进 `#page-body`**：保存成功后会调 `loadAll()`
  整块重渲染 `#page-body`，挂在里面会连弹层一起销毁，用户看到的是"弹层自己消失了"。
- **`z-index: 180`，低于 toast 的 `200`**：弹层里保存成功的提示要能浮在遮罩之上被看见。
- **遮罩自己设了 `display: flex`，隐藏态必须显式写 `.zdlg-mask[hidden] { display: none }`** ——
  作者样式会盖掉 UA 的 `[hidden]`。任何设了 `display` 的元素，若还要靠 `hidden` 属性控制显隐，
  都得补这一行（`.zdlg-msg` 同理）。
- **打开时给 `body` 加 `is-dlg-open`（`overflow: hidden`）**，否则背景跟着滚、
  弹层却钉在视口中央，割裂感很强。
- **关闭时把焦点还给触发按钮**，且触发元素由调用方传入（`openUserDialog(u, this)`），
  不要读 `document.activeElement`：程序化 `click()` 不会给按钮聚焦，读到的是 `<body>`，
  焦点就丢了。键盘用户不该被扔回页面顶部。
- **前端校验与后端逐条对齐**（邮箱/手机正则、昵称长度）。前端只为省掉一次注定 400 的请求，
  最终以后端为准；两端正则要同步改，否则会出现"前端放过去、后端打回来"。
- **多接口写入先做最可能失败的那一步**：改角色走 `/users/{id}/role`、改资料走
  `/users/{id}`，顺序是先角色后资料。反过来的话，角色被「最后一个管理员」拦下时
  昵称已经改了，留下半截状态。
- **同一弹层要能服务多行数据时，所有状态必须每次打开都显式复位**。踩过的坑：
  「断开接入」按钮成功后会 `.prop('disabled', true)` 防重复提交，而弹层是四个模型共用的
  同一个实例 —— 断开过一次之后，其余模型的断开按钮就永远点不动了，只能刷页。
  凡是"提交时禁用、成功后关窗"的按钮，都要在打开时把 `disabled` / `data-armed` / 文案一起复位。
- **别在关窗之后才读被关窗逻辑清空的变量**。`closeModelDialog()` 会把 `mdlgModel` 置空，
  紧接着 `toast('「' + mdlgModel.name + '」已断开')` 就是 `TypeError`，
  而它发生在 `.then()` 里，会被后续的 `.catch()` 吞掉或直接静默，表现只是"提示不出现"。

### 3.6 重渲染后保留焦点

`paint()` 用 `.html()` 整块替换 `#page-body`，会把焦点所在节点一起销毁，焦点掉到 `<body>`。
保存/断开/启用/停用这类操作都会触发重渲染，**时序上还常常是"先归还焦点、接口才返回、这才重渲染"**，
刚还回去的焦点又被换掉。做法是在替换前按 `data-*` 身份记下来、画完再找回来：

- 记的是**身份**（`data-model-key` / `data-action` / `data-account`），不是节点引用 ——
  重渲染后节点全换，引用必失效。
- 只接管**确实位于 `#page-body` 内部**的焦点：弹层挂在 `<body>` 上，不在替换范围内，
  它自己的焦点不该被这里抢走（否则重渲染会把焦点从弹层输入框里拽出来）。
- 找不到对应元素时**静默跳过**，不要退而求其次聚焦"同位置"的其它按钮 ——
  那条待办可能刚被处理掉，聚焦到错的按钮比不聚焦更误导人。

## 四、JavaScript 规范

### 4.1 命名空间与模块职责

全局只暴露一个对象 `window.ZFZ`，其余全部封装在 IIFE 内：

| 模块 | 职责 | 允许依赖 |
|---|---|---|
| `ZFZ.api` | 接口契约，唯一发请求的地方 | jQuery |
| `ZFZ.ui` | **纯函数**：入参 → HTML 字符串，不碰 DOM、不发请求。空态/错误态/格式化助手都在这层 | 无 |
| `ZFZ.layout` | 顶栏/导航/页头骨架 + 全局交互（搜索/通知/用户菜单） | jQuery、ZFZ.ui |
| `js/pages/*.js` | 单页：取数 → 调用 `ZFZ.ui` 拼装 → 注入容器 → 绑事件 | jQuery、ZFZ.ui、ZFZ.api |

> 早前的 `ZFZ.mock` 演示数据层已物理删除（`js/data.js` 移除、`api.js` 的 `useMock`
> 开关清零），因此不再出现在上表中 —— 接口失败必须如实报错，不得静默回退假数据。

### 4.2 模块骨架（所有 JS 文件统一）

```js
/* ==========================================================================
   模块标题
   一句话说明本模块职责
   ========================================================================== */
(function ($) {
  'use strict';

  var U = ZFZ.ui;                 // 常用依赖提到顶部，别处不再写前缀

  /** 函数级 JSDoc，见 4.4 */
  function someFunction(arg) { … }

  /* ---------------- 分区注释：用小节线分隔逻辑块 ---------------- */

  $(function () { … });           // 入口：DOM ready
})(window.jQuery);
```

### 4.3 命名约定

| 对象 | 规则 | 示例 |
|---|---|---|
| 函数 / 变量 | 小驼峰 | `mapCanvas`、`nextPhotoTransform` |
| 常量 | 全大写下划线 | `MW`、`MH`、`LNG0`、`RISK` |
| DOM id | 连字符 | `#btn-snapshot`、`#timeline-play` |
| CSS 类（JS 里选中的） | 同 CSS，连字符 | `.map-canvas`、`.zbar-fill` |
| 布尔量 | `is` / `has` 开头 | `isOpen`、`hasMore` |
| 页面模块 | 文件名 = 页面路由 | `forecast-disagreement.html` ↔ `pages/disagreement.js` |

### 4.4 JSDoc 注释标准

**(1) 文件头**：`@file` + `@description`，重要的还要 `@example`、`@see`。

```js
/**
 * @file 追风者 · 接口层（RESTful 契约）
 * @description 统一封装与后端 Servlet 的交互；开发阶段返回模拟数据。
 * @example
 *   ZFZ.api.getTracks(13).then(function (list) { … });
 */
```

**(2) 公共函数**：必须写 `@param` / `@returns`，返回值是 Promise 或复合对象时用 `@returns {Promise<{…}>}` 描述结构。

```js
/**
 * 查询台风的实况轨迹点序列。
 * @param {number|string} id 台风 id
 * @returns {Promise<Array<{time: string, lon: number, lat: number}>>} 轨迹点数组
 */
```

**(3) 私有函数**：加 `@private`，可省 `@param` 的详细描述。

**(4) 分区注释**：每个逻辑分区用一行小节线，不写无意义注释。

```js
/* ---------------- 左列：台风列表 ---------------- */
```

**(5) 禁止的注释**：`// 循环 i 从 0 到 n` 这类复述代码的注释；
注释要写「为什么这么做」，不是「做了什么」。

### 4.5 数据与 DOM 操作约定

| 约定 | 说明 |
|---|---|
| HTML 一律字符串拼装 | 不用模板引擎（课程禁用前端框架）；字符串拼接便于审查 |
| 输出用户/接口数据必须转义 | 统一用 `U.esc(str)`，防 XSS |
| 事件用委托绑定 | 绑在稳定的父容器（如 `#page-body`）上，避免重新渲染后失效。**判断标准**：该节点是否可能被"绑定时那次之外"的代码路径重建？只要有可能（如分页条每次翻页都 `replaceWith` 整条重建），就必须委托——直绑的表现是"只有第一次交互生效"，且不报任何错 |
| 读 `data-*` 用 `.attr()` | **被 JS 改写过的 `data-*` 必须用 `.attr()` 读写**，`.data()` 会缓存首次值 |
| 不写行内 `onclick` | 会破坏 CSP，也无法统一管理 |
| 不定义全局变量 | 除 `window.ZFZ` 外不新增全局 |
| 图表用原生 SVG | 折线/柱状/环形均为函数返回的 SVG 片段，不引第三方图表库 |

### 4.6 接口调用约定

页面**只调用 `ZFZ.api` 的方法**，不直接写 `$.ajax`：

```js
// ✅ 正确
ZFZ.api.getForecastPaths(id).then(function (paths) { render(paths); });

// ❌ 禁止：页面直接请求，绕过统一错误处理与 mock 开关
$.get('/api/typhoons/' + id + '/forecast-paths', function (res) { … });
```

**列表分页**：需要总数时用 `ZFZ.api.getTyphoonsPage(params)`，它返回
`{items, total, page, limit, pages}`；`getTyphoons()` 只吐数组，是为兼容
"只要一组数据"的历史调用点而保留的壳。

```js
// ❌ 禁止：拿数组长度当总数 —— 那只是"当前页条数"，翻页后长度不变，
//    分页会永远算成只有 1 页
ZFZ.api.getTyphoons(params).then(function (list) { var total = list.length; … });

// ✅ 正确
ZFZ.api.getTyphoonsPage(params).then(function (r) {
  renderRows(r.items);            // 当前页
  renderPager(r.page, r.pages);   // 分页条
  setSub('共 ' + r.total + ' 条'); // 总数
});
```

**换检索条件时必须回到第 1 页**：停在第 3 页去查一个只有 1 页结果的关键词，
会直接看到"没有匹配的档案"，让人误以为关键词没命中。

### 4.7 空态 / 错误态 / 格式化：一律用 `ZFZ.ui`，禁止在页面里重复实现

2026-10-12 的整合把此前**被复制到各页**的助手统一收拢进了 `ZFZ.ui`。
新写页面时必须直接调用，**不要再在 `js/pages/*.js` 里重新实现一份**。

| 助手 | 产出 | 用途 |
|---|---|---|
| `U.esc(s)` | 转义后的字符串 | 任何插入 HTML 的动态文本 |
| `U.emptyRow(text)` | `<div class="empty-row">…</div>` | 空态 / 提示行；`text` 会被转义 |
| `U.errorBody(message)` | 上述形态 + 「加载失败：」前缀 + 请检查后端的尾注 | 错误态正文 |
| `U.errorPanel(title, message)` | `U.panel` 包起来的错误卡片 | 整块错误态 |
| `U.loadingRow()` | `U.emptyRow('加载中…')` | 首屏占位 |
| `U.num(v, fallback)` | 数字或回退值（`isFinite` 判定） | 后端字段转数字 |
| `U.fixed1(v)` | 保留 1 位小数的字符串，空值 `—` | 数值展示 |
| `U.pad2(n)` | 两位补零字符串 | 拼时间文案 |
| `U.fmtTime(s, withTime)` | `YYYY-MM-DD[ HH:mm]`，空值 `—` | 后端时间串展示 |

三条硬性注意：

1. **不要用 `U.emptyRow()` 包已经 `esc` 过的内容**——会二次转义。
   需要「前缀 + 变量」时写成 `U.emptyRow('查询失败：' + err.message)`，
   把原始值交给 `emptyRow` 去转义一次即可（`esc` 对字符串拼接是可分配的）。
2. **同名但语义不同的助手必须留在页面里**，不要为了"看起来统一"而强行合并：
   `overview.js` 的 `num(v)`（`null → '—'`）、`sandbox.js` 的 `num(v)`（补一位小数）、
   `disagreement.js` 的 `numOr(v, fb)`（用 `isNaN` 判定，与 `U.num` 的 `isFinite`
   对 `Infinity` 行为不同）都属于这一类，**已刻意保留在原地**。
3. 各页允许保留一行本地绑定（如 `var errorPanel = U.errorPanel;`）以保持调用点不动，
   但**不允许**再出现第二份实现体。

### 4.8 响应式与可访问性

- 适配断点：1440（设计基准）→ 1280 → 1024（平板横屏），主内容列收缩、列距变窄；
- 所有图标按钮给 `aria-label`，下拉触发器给 `aria-haspopup`；
- 键盘可达：下拉面板支持 `Esc` 关闭，可点元素用 `<button>` / `<a>` 而非 `<div>`。

### 4.9 派生分析结果：用 `analyzeTarget` 选台风，用 `switchNote` 明写回落

AI 测算 / 预报分歧 / 风险预评估 / 公众调研看板这四类**派生结果**，最新的活跃台风未必算得出来
（对外可用的多机构预报只有中央气象台一家、风圈半径内没有中国城市、刚同步进来的台风零问卷样本）。
这些页面**一律**按同一段代码选目标台风，不要各写一套：

```js
ZFZ.api.getTyphoons({ status: 'ACTIVE' }).then(function (actives) {
  return ZFZ.api.analyzeTarget({
    base: actives[0],                  // 默认 = 最新活跃台风
    actives: actives,                  // 候选，按"最新优先"顺序逐个探测
    probe: function (id) {             // 返回 Promise<boolean>：这条台风算不算得出来
      return ZFZ.api.getXxx(id).then(
        function (d) { return /* 有内容 */ true; },
        function () { return false; });// 接口失败 = 算不出来，而不是抛错中断整页
    }
  });
}).then(function (target) {            // { typhoon, switched, reason, base }
  $body.html(U.switchNote(target, '……算不出来的一句话原因') + /* 正常内容 */);
});
```

四条硬性要求：

1. **同一页里「实况」与「分析」是两个不同的台风 id，不可合并**。例如 `overview.js`
   的地图图层跟 `state.live`（最新活跃台风），右栏 AI / 风险卡片跟 `state.analysis`（回落台风），
   并在容器上打 `data-live-typhoon` / `data-analysis-typhoon` 供回归脚本断言。
   问卷页同理：**填写的问卷记到最新活跃台风**（`state.typhoonId`），
   **看板聚合跟随回落台风**（`state.aggTyphoonId`）。
2. **回落必须显式告知**——用 `U.switchNote(info, why)` 渲染提示条。静默替换比空态更危险：
   用户会以为看到的就是最新台风的结果。未发生回落时它返回空串，不占位。
3. 地址栏带 `?id=` 时**尊重显式指定**、不做回落（`reason === 'explicit'`）。
4. 回落选中的仍然是**库内真实记录**，不允许为了"页面不空"而造数。

### 4.10 地图：经纬度写在数据里，视野由 `fitBox` 决定

**背景**：地图投影把经纬度映射到固定的画布窗口。P1 实况图与 P6 沙盘图 2026-10-18 起
**共用同一个窗口 804×462 ≈ 100°E—180°E / 4°N—50°N**（西北太平洋台风活跃区）。
早先的设计稿窗口是 `804×640` ≈ 105°E—135°E，活跃台风多在南海—东海，这条假设成立；
接入中央气象台真实数据后，台风完全可能在西太平洋远洋——实测轨迹最东到 **179.4°E**，
在旧窗口里整条轨迹被投到数千像素之外，**远在画布之外**，页面看起来像"路径线消失了"。

现在窗口本身就覆盖到日期变更线，`fitBox()` 对绝大多数台风返回**恒等视野**（不再自动缩小）；
它只在小窗口场景（如 P3 热力图）或极端越界时兜底。

**约定**：所有按经纬度绘制的地图，渲染前必须先用 `ZFZ.ui` 内部统一的 `fitBox()` 求视野，
再让**底图、矢量层、HTML 浮层标注**共用同一套变换。三条硬性要求：

1. **判据是"数据是否完整落在画布内"，不是"数据跨度是否小于画布"**。
   后者会漏掉"跨度不大、但整体偏到画布外"：沙盘图的路径点彼此只差几十像素，
   却整体位于画布右侧 2000px 开外，只看跨度会算出 `s=1`，于是既不缩放也不平移，线依然不可见。
2. **变换必须成对**：`p' = (p − c)·s + c + t`。SVG 写
   `translate(t + c) scale(s) translate(−c)`，底图 `<img>` 写
   `translate((t/W·100 + 50)%, …) scale(s) translate(-50%,-50%)`（配合 `transform-origin: 0 0`）。
   只减 `c` 不加回来，会让整个图层额外平移半个画布宽——表现为"路径贴到画布边缘"。
3. **常态零变换**：数据本来就装得下时 `auto=false`，渲染结果与设计稿逐像素一致；
   只有越界才缩放，并由页面在角上**明示**（`map-view-note` / `lmap-view-note`，文案含缩放百分比），
   不要静默改变视野。
   ⚠️ 具体表现是「`<g class="map-view-g">` **恒产出**，恒等视野时只是不带 `transform` 属性」
   ——**不要**把它"优化"成"恒等就一个节点都不加"：那样用户缩放时只能重建整棵 SVG，
   既会闪，还会把底图选择与图层开关的勾选状态一并冲掉（原因见 §4.13）。不带 `transform`
   的 `<g>` 在渲染上等价于不存在，因此这条改动不影响与设计稿的像素一致性。

越界时底图可能整体移出画面，此时**必须补一层与底图同投影的经纬网**（`.map-grat` / `.lmap-grat`），
否则画布只剩一片空白，用户会以为又坏了。容器上要打 `data-view="scale,tx,ty"`，
出问题时可以直接读，不必反推像素坐标。

### 4.11 检索条件：能用下拉就不要用静态文本

档案页（P8）的检索条件曾把「年份 / 峰值强度 / 海域 / 状态」渲染成 `U.fieldBox` 的**静态文本**，
只有名称能输入——用户看到四个"框"却点不动，等于把后端早就支持的 `year` / `minWindForce` /
`basin` / `status` 四个参数藏了起来。**凡是后端支持的筛选维度，前端都要给出可操作的控件。**

- 用 `U.fieldSelect(label, id, options, selected)`，外观与 `U.fieldBox` / `.field-input` 一致；
- **选项一律来自接口**（`GET /api/typhoons/meta` 的 `years` / `basins` / `statuses`），
  不在前端写死年份清单；
- **第一项固定是「全部…」，其值为空串**，后端见到空串会跳过该条件——这是"任意组合筛选"的前提；
- 选项值与选中值的比较**统一转成字符串**：年份来自接口是数字，状态是字符串，
  直接 `===` 会让回填选中项静默失效；
- 「重置条件」必须把**全部**下拉一起清回第一项，只清名称属于名不副实；
- 结果区副标题要写明**当前生效的条件**（用 `filterSummary`），否则用户分不清"没有数据"和"条件太窄"；
- **分组下拉（`optgroup`）必须先归拢再拼**：`fieldSelect` 是"遇到 `group` 变化就开一个新
  `<optgroup>`"，如果按接口返回顺序直接 `push`，活跃与历史交错返回时会被切成好几段同名分组
  ——风险评估页实测出现过 **5 段交替**（`历史档案:1 / 活跃台风:1 / 历史档案:4 / 活跃台风:1 /
  历史档案:37`）。正确做法是先按分组字段分桶，再 `concat`，保证恒定产出 2 个 `optgroup`。
  **不要假设接口已经排好序。**

> 同一条规则也适用于风险评估页（P4）：它顶部的「城市 / 关联台风 / 评估基准」原先是
> `U.chips` 渲染的**只读文字**，只能被动接受 `analyzeTarget` 自动挑中的台风。现已改为三个
> `U.fieldSelect`。特别地，**「评估基准」原先显示的是浏览器当前时间，是假数据**——服务端推算
> ETA 的起点是台风的某个**实测时刻**，两者口径不一致。现在基准由服务端随结果回传
> （`RiskAssessmentVO.baseTime`），下拉的每一项就是一个真实观测时次。
> **凡是页面上显示的时间，都要问一句"它和后端算出来的用的是同一个基准吗"。**

### 4.12 列表项的主行为变了，就该换元素：`<a>` → `div[role=button]`

监测总览（P1）左栏的台风列表项原来是 `<a href="typhoon-detail.html?id=…">`，点击即跳详情页。
需求改成"点击就在右侧地图上聚焦该台风"之后，**不能继续用 `<a>`**：

- 一个可点区域里再嵌一个链接（行内「详情」）属于**嵌套交互元素**，键盘 Tab 顺序与读屏
  播报会变成"链接、链接、详情、链接"，语义混乱；
- 主行为是**纯前端状态切换**，用 `<a href>` 会让地址栏也被改掉——用户刷新一下就"回"到了
  详情页，与预期完全不符。

**约定**：主容器用 `div[role="button"][tabindex="0"]` + `data-ty-id`，行内保留**真正的**
`<a>` 指向详情页（保住中键 / ⌘ 点击在后台标签页打开的浏览器原生习惯）。同时必须做到：

- `role=button` 的 `div` **不会**把 Enter / Space 自动转成 click，页面要自己绑 `keydown`
  （少这段，纯键盘用户就只剩「详情」链接可用）；
- 必须补 `:focus-visible` 焦点环——`<a>` 时代有浏览器默认焦点环，换成 `div` 就没了，
  Tab 过去完全看不出焦点停在哪一行；
- 点击处理里要放行行内链接与修饰键：
  `if ($(e.target).closest('.ty-item-detail').length) return;`
  `if (e.metaKey || e.ctrlKey || e.shiftKey || e.altKey || e.which === 2) return;`

推广：**凡是"点击后切换的是页面内状态"的元素，都不要做成带 `href` 的链接。**

### 4.13 地图视野分两层：`FIT`（自动适应）⊕ `ZOOM`（用户操作）

`fitBox()` 解决的是"**程序**能不能看见"，但用户还需要"**我**想怎么看"——放大看某一段路径的
细节，或缩小把周边海域纳进来。这是两件事，必须分层，否则"自动"会不断覆盖"手动"：

- `FIT` = `fitBox()` 的结果，只在 `mapCanvas()` 渲染时算一次；
- `ZOOM` = `{k, px, py}`，用户倍率与平移，由 `bindMapView()` 维护；
- **实际视野 `VIEW` = `composeView()`**，把用户操作**折叠进同一个视野对象**：

  ```
  s = b.s · k          t = b.t · k + p
  ```

  这一点是关键——**不要"在 SVG 里再套一层 transform"**。折叠之后 `viewSvgTransform` /
  `viewCssTransform` / `viewApply` / `viewUnproj` 一行都不用改；再套一层的话，锚点公式、
  经纬网反投影、HTML 浮层定位就要各自维护一套坐标换算，迟早对不上。

配套约定：

- **锚点缩放**：滚轮必须按光标位置缩放，公式 `p′ = pu − c − (k′/k)·(pu − c − p)`
  （`pu` 为锚点画布坐标）。**先夹倍率、再算平移**，否则缩到极限后地图会持续漂移；
- **原地更新**：`syncView()` 只改属性、不重建节点，且必须同步 **4 处**——
  矢量层 `.map-view-g` 的 `transform`（**底图已并入这一层**，与真实海岸线共用同一个变换，
  见 §4.14）、经纬网图层（内容随视野重算）、右下角提示条与动态比例尺、
  容器上的 `data-view` / `data-zoom` / `data-lod` / `--lbl-k` 与控件上的百分比。
  **漏掉经纬网那一处，网格就会和海岸线错位**；
- **经纬网恒在 DOM 且恒显示**：它现在是常态可见的图层（见 §4.16），内容随视野重算；
  不要"没有就不产出"——那样缩放时只能重建 DOM，会闪，还会冲掉底图与图层开关的勾选状态；
- **每次 `mapCanvas()` 重建都清零 `ZOOM`**：换了台风之后，上一个台风的平移量没有任何参考
  意义，留着只会让人一脸茫然；
- **只有需要缩放的图才带控件**：`mapCanvas({zoom: true})` 才产出 `.map-zoom` 并接管滚轮；
  空态 / 加载态**不传**（否则一个空底图也能拖能缩，看起来像界面坏了）；
- **提示条文案要分自动 / 手动**：自动时说"为完整显示台风路径，地图已自动缩放至 N%"，
  手动时必须补上"可拖拽平移，点「重置」回到自动适应视野"——地图被拖歪之后，
  没有这句用户只会以为页面坏了。
- **视野要夹在有数据的范围内**（`BOUND` + `clampPan()`，见 §4.13.1）。宁可拖不动，
  也不能让用户拖进"没有数据的地方"。

### 4.13.1 视野边界：为什么必须夹住，且为什么 100% 就到底

地形晕渲是一张**有覆盖范围**的位图（DEM 92°E—178°E / 4°N—52°N，见
`docs/terrain-basemap.md`）。位图以外没有高程，陆地只剩 `.map-land` 的一层平涂底色、
海面直接透出容器底色——于是图面上会出现一条笔直的「地形到此为止」的直角分界线：
一侧有晕渲、分层设色和等高线，另一侧是一块死色。

2026-10-18 实测到这个问题：把地图往西 / 北拖到 92°E、52°N，画面上就出现一个巨大的
亮暗矩形（用户的原话是「这些空白的地方……会有很强的割裂感」）。它不是 CSS 坏了，
是**视野离开了数据**。两条约束一起上：

1. **`BOUND`（`clampPan()`）**：可见矩形必须落在 `BOUND` 内，反解出 `t` 的上下界
   （推导写在 `ui.js` 的注释里）。边界取 DEM 的 92°E / 4°N / 52°N 与画布右缘 180°E
   —— 东边那 2°（178—180°E）是开阔洋面，位图海面 `alpha=0`、两侧同色，不会留痕。
   夹的是 `ZOOM.px/py` **本身**（不是只在合成时夹返回值），否则拖到边界后再往回拖，
   那段被"吃掉"的越界量会让地图黏住不动。
2. **`ZOOM_MIN = 1`**：100% 时整个台风区刚好装满画布，再缩小只会把视野推到 DEM 之外。
   于是「−」在 100% 就是死的——**必须置灰**（`syncZoomButtons()` 写 `disabled`），
   不能让按钮点了没反应，那是"按钮坏了"的观感来源。

例外：自动适应（`FIT.auto`）本身选定的位置**永远可达**。万一某个台风跑到 100—180°E
之外，`fitBox()` 会平移把路径纳入画布，此时若一律夹回框内，路径反而被裁掉——
所以 `clampPan()` 把区间放宽到"至少包含自动视野"。

回归脚本：`tools/probe-map-bounds.cjs`（17 项：四向拖到底的边界值、地形位图是否盖住画布、
「−」的置灰时机、重置后回到恒等视野）。

回归脚本：`tools/probe-overview-focus.cjs`（36 项断言，覆盖切台风、按钮 / 滚轮 / 拖拽缩放、
重置、历史分组、返回最新）。基线务必取"切换台风**之后**"而不是"页面初始"：
换过台风地图会按新数据重算自动视野，拿页面初始那个台风的比例尺来比，比的是两个不同的台风。

### 4.14 底图只有一层：全部由真实海岸线生成（设计稿底图已废弃）

**背景（三项修复的演进）**：

1. §4.10 的视野自适应解决了"路径画到画布外"；
2. 但**没有解决观感**——台风在 157°E 时 `fitBox` 会把视野缩到 45%，三张设计稿底图随之
   缩成角落里的一小块，其余 2/3 画布全是空海面，地图看起来像坏了；
3. 于是加了一层"远洋真实海岸线"垫底，形成**双层底图**。双层能兜住观感，却仍有两个病根：
   ① 缩小时上层那张 804×640 位图与下层矢量岸线叠在一起，边界处纹理对不齐，一眼就是"拼的"；
   ② 更要命的是**经纬网 / 云图 / 地名三类信息全被那张位图框住**——出了 105°E—135°E
   三样同时消失（这是用户第三次反馈，触及了根因）。

**结论：废弃设计稿底图，底图只保留一层，完全由 `js/geo-wpac.js` 的真实海岸线绘制。**
一份几何、三套 CSS 配色（普通 / 卫星 / 地形），三类信息（经纬网 / 云图 / 地名）都挂在这一层
之上，因此走到哪都能覆盖到。

| 项 | 值 |
|---|---|
| 数据源 | Natural Earth（public domain），`tools/gen-wpac-coast.py` 生成 |
| 生成范围 `pad` | `[-1600, -1600, 3600, 2200]` → 覆盖约 **45°E—239°E** |
| 实测体积 | 104.3 KB / 748 环 / 19580 点 |
| 配色 | 只有一组 `--map-ocean/land/coast`（2026-10-18 三合一后不再分 `-sat` / `-ter`） |

要点（1—5、7 为旧版沿用，仍然成立）：

1. **投影参数与 `ui.js` 的 `proj()` 完全同源**，岸线才能和台风路径逐点对齐；
2. **经度必须逐环展开**，不能"凡 `<79°E` 就 `+360`"。欧亚大陆是西起欧洲、东至白令海峡的
   巨型多边形，那种粗暴归一会在海里拉出一条横贯全图的假边。正确做法见脚本的 `unwrap()`：
   按相邻点差展开成连续经度，再把整环保留 360° 的整数倍平移到目标区间；
3. **裁剪要用 Sutherland-Hodgman，不能"逐点过滤 + `Z` 闭合"**，后者会把跨边界的大陆
   截断后首尾直连，海里凭空多出斜三角；
4. **同一个多边形的外环与孔洞要合成一个 `<path>`**——`fill-rule="evenodd"` 不跨 `<path>`
   生效，拆开的话里海、黑海会被填成陆地；
5. **海面用容器底色，不要用图层里的 `<rect>`**：视野虽有 `BOUND` 夹着（见 §4.13.1），
   但海岸线数据的覆盖范围（45°E—239°E）远大于画布，任何固定大小的矩形都不可能
   与可见范围刚好重合，边界处必然露出原始底色（见 `app.css` 的 `.map-canvas`）；
6. **path 片段缓存一次**（`LAND_INNER`，由 `landInner()` 产出）：748 条 path、约 104 KB，
   每次 `mapCanvas()` 重建都重拼一遍纯属浪费；
7. **底图与矢量层共用一个 `.map-view-g` 变换**：底图不再是 `<img>`，而是同一张 SVG 里的
   一个 `<g>`（`lyrLand()`），所以 `viewCssTransform()` 这套「CSS 变换的等价表达」已彻底删除
   ——少一套必须与 SVG 保持一致的换算，就少一处会错位的地方；
8. **设计稿底图的四边羽化规则一并删除**：底图既然只有矢量一层，就不存在"装饰网格硬分界"，
   `mask-image` / `mask-composite` 那两条 `[data-view]` 规则已移除。

**数据是静态的，但生成脚本要留在仓库里**：换精度（`50m` / `110m`）或改覆盖范围时重跑即可
（`python tools/gen-wpac-coast.py [精度] [x0 y0 x1 y1]`），不要手改 `geo-wpac.js`
（文件头已标注"自动生成，请勿手改"）。

### 4.15 云图是独立图层，三合一后常显

云图**不是底图的一部分**，而是一个独立 SVG 图层 `.map-cloud-layer`（`data-layer="cloud"`）：

- **2026-10-18 三合一后常显**：普通 / 卫星 / 地形已经合并成一张图，`[data-basemap]` 属性
  与切换按钮一并删除，云系不再需要"切到卫星底图才出现"。浓度压到 `.cloud-tex{opacity:.18}`，
  否则会盖住下面的地形晕渲（三合一之前是 .55，那时云下面没有地形）；
- **云是示意产品，不是观测数据**——图例必须如实写「云系示意（非观测产品）」。
  本项目"数据全真不造数"，云图是唯一的例外，就靠这句标注把边界划清楚，绝不能让人
  误以为是真实卫星云图；
- **生成方式**：`feTurbulence`（`baseFrequency 0.0055 0.009`、3 octaves、`seed 17`）
  + `feColorMatrix` 把斜率/截距压到 `k=2.00 / c=-2.85` 逼出高对比云带；柔边云团用
  `radialGradient`（`zfzCloudSoft`）叠加——**不要逐个云团挂高斯模糊**，那是 N 次滤镜栅格化；
- **随机数要用线性同余**（`lcg(20261014)`）**保证确定性**：否则每次 `mapCanvas()` 重建都
  换一张云图，刷新一次变一次，看起来像 bug；
- **`defs` 放独立作用域**：滤镜与渐变放在 `<svg class="map-defs">`（宽高 0）里，**不要**塞进
  `display:none` 的图层里——隐藏容器中的 `defs` 在部分浏览器上引用会失效；
- **浓淡要克制**：`.cloud-tex { opacity: .55 }`、云团 `0.16 + rnd()*0.34`。第一版用了
  `opacity: .46` + 云团 `0.25+rnd()*0.5`，截图整张灰白，海岸线和地名全糊住——云图是背景，
  别把它做成了主角；
- **性能实测**：切到卫星底图并稳定两帧仅 **13—18 ms**（`tools/shot-map-look.cjs` 内置计时），
  说明滤镜没有按 5000×3800 逐像素渲染，可以放心挂。

### 4.16 地名与经纬网：写在数据里、按比例尺分级、字号反缩放

三类信息里，地名与经纬网是**全底图通用**的（普通 / 卫星 / 地形都显示），规则如下。

**地名表 `PLACES`**（约 110 条，`ui.js` 内静态常量）：

- 每条形如 `[名称, 经度, 纬度, 类别, 优先级, 可选{a,dx,dy}]`，类别为 `sea` / `country` /
  `prov` / `city`；**一律给经纬度、由 `proj()` 投影**，绝不写死画布像素；
- **地名表述要合规**：统一写「台湾地区」「香港特别行政区」「澳门特别行政区」「南海诸岛」，
  不写成国家或独立地区；
- 类别覆盖：海域 14 条（渤海 / 黄海 / 东海 / 南海 / 南海诸岛 / 菲律宾海 / 日本海 /
  鄂霍次克海 / 西北太平洋 / 孟加拉湾 / 阿拉伯海 / 泰国湾 / 爪哇海 / 珊瑚海）、
  国家与地区 21 条、中国省级 29 条、城市 44 条。

**按比例尺分级（LOD）**：`lodLevel(s)` → `s>=0.55 → 3`、`s>=0.32 → 2`、否则 `1`；
容器打 `data-lod`，CSS 三条规则按 `is-lv1/2/3` 决定各粒度是否可见。缩小时只剩海域与国家，
放大后才逐级冒出省与城市——**同一屏上的地名数量必须受控**，否则缩到 28% 时满屏文字。

**字号反缩放（`--lbl-k`）**：容器上写 `style="--lbl-k: 1/s"`，地名 / 刻度 / 城市圆的
`font-size` / `r` 写成 `calc(基准px * var(--lbl-k))`，**屏幕字号恒定**。
不做反缩放的话，缩小时地名跟着 SVG 一起缩到看不见、放大时又大得糊脸。
SVG 的几何属性（如圆的 `r`）也可以直接写在 CSS 里配合 `--lbl-k`。

**经纬网**：

- **恒定显示**（不再"只在缩放时出现"），且**恒定在 DOM**，`syncView()` 只改内容；
- 步长自适应：`GRAT_STEPS = [1,2,5,10,20]`，取第一个让**可见跨度内线数 `<= 10`**
  （`GRAT_MAX_LINES`）的步长——1° 用到 10°，缩得越远网格越疏；
- 经度标签换算成 E/W（`gratLonLabel`），纬度超出 ±85° 跳过（`gratLatLabel`，避免极点处挤成一团）。

**动态比例尺 `.map-scale`**：`SCALE_STEPS = [50,100,200,500,1000,2000,5000,10000]`，
取屏幕长度 `>= 70px` 的最小整距离，随缩放 / 平移重算（`KM_PER_PX = 3.9`）。

回归脚本：`tools/shot-map-look.cjs`（三套底图截图 + 逐个打印 `landPaths / lod / lblK /
lblFont / cloudShown / gratLines / places / scaleText`，并计时底图切换）、
`tools/probe-overview-focus.cjs`、`tools/probe-map-paths.cjs`。

### 4.17 筛选联动：条件卡常驻，只重绘结果区

**背景**：风险评估页（P4）三个下拉选完即重算。若每次都整页重建，用户刚点开的 `<select>`
会被替换掉——焦点与展开状态丢失，看起来像"点了没反应"，事件绑定还得每次重做。

**约定**：

- **条件卡常驻**：给它一个固定 id（如 `#risk-filter`），重绘时只清它的**后续兄弟节点**
  （`$('#risk-filter').nextAll().remove()`），条件卡本体不动；
- **只有"选项集合变了"才整卡重建**——风险评估页里仅「关联台风」会连带改变基准时次列表，
  所以只有换台风时 `replaceWith` 整卡（此刻用户已离开该控件，不会丢焦点）；
  换城市 / 换基准只原地同步 `option`（`U.fieldOptions` + `$sel.val()`）；
- **跨字段联动用一份显式 `state`**，而不是每次去读 DOM：换台风要连带重置基准时次，
  这种逻辑靠读 DOM 很容易漏；DOM 只作展示层，在 `render()` 末尾统一回填；
- **"用户动过下拉"要记一个 `manual` 标记**：自动改选台风的提示（`U.switchNote`）只在
  用户还没手动选过时显示，一旦他自己选了就以他为准，**不再偷偷改选**。

**主卡聚焦 vs 侧栏全量**：侧栏「距离测算 · 周边城市」天生要全部城市，所以每次取**全量**，
主卡再在本地筛出选中城市（零额外请求）。只有"选中的城市不在全量列表里（超出评估半径）"
时才补一次单城市请求——**让"距离较远、暂不构成风险"这句话由后端给出**，而不是前端自己编，
这样全站口径只有一个。

回归脚本：`tools/probe-risk-filters.cjs`（14 项断言：三个下拉是 `<select>`、分组恒为 2 段、
换城市主卡聚焦、换基准后结果卡的基准时刻随之改变、条件卡未被重建、未登录存档走 401 提示、
零控制台错误）。
