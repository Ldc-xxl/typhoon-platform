# 地形图（terrain basemap）

「地形图」不是普通地图换个颜色，而是**带真实高程的独立图层**。本文说明它由什么组成、
数据从哪来、怎么改。

> **2026-10-18 三合一**：普通地图 / 卫星云图 / 地形图不再是可以切换的三张底图，
> 海岸线、地形晕渲、云系**同时**叠在同一张图上（`data-basemap` 属性已删除）。
> 本文档里"地形图"一词现在指那张合成图里的**地形图层**，
> 它与其他两个图层的关系见 `docs/frontend-integration-guide.md` 的地图章节。

## 一、它由什么组成

制图学上表达地形的三个要素，本项目都做了：

| 要素 | 作用 | 实现 |
|---|---|---|
| **晕渲** hillshade | 立体感 | 由 DEM 的坡度/坡向算光照强度（方位角 315°、高度角 42°） |
| **分层设色** hypsometric tint | 高低分布 | 按高程分 9 档着色（绿→褐→白），色标见 `gen-terrain.py` 的 `HYPSO` |
| **矢量等高线** contour | 精确读高程 | marching squares 提取，**矢量故放大到 600% 也不糊** |

另加**高程点**（局部高点 + 高程数字）。

## 二、数据来源

真实 DEM，不是示意：

```
AWS Terrain Tiles（Terrarium 编码，RGB 编码高程）
  → tools/fetch-dem.py     抓取 92°E—178°E / 4°N—52°N（z7，672 张瓦片）
  → tools/gen-terrain.py   晕渲+设色位图、等高线、高程点
  → js/geo-wterrain.js     等高线与高程点（画布像素坐标）
  → assets/terrain/terrain-hillshade.png   晕渲+设色底图（RGBA，海面透明）
```

高程来自 SRTM / NED / ASTER 等公开 DEM。
已用玉山（3952m）、富士山（3776m）、泰山（1532m）、珠峰（8849m）实测校验。

## 三、改动流程

```bash
# 1. 抓 DEM（首次约 9 分钟；已缓存则秒过）
python tools/fetch-dem.py

# 2. 渲染 + 生成矢量数据（改 HYPSO / CONTOUR_STEPS / OVER 后重跑）
python tools/gen-terrain.py                 # 默认 2× 超采样
python tools/gen-terrain.py --over 1.5      # 降体积
python tools/gen-terrain.py --coarse 2      # 等高距整体放大（体积超预算时）

# 3. 验证
node tools/probe-terrain-map.cjs            # 32 项断言
node tools/shot-terrain-compare.cjs         # 出一张「改造前 vs 改造后」对照图

# 4. 同步到两个部署目录（见 MEMORY.md 的部署约定）
```

## 四、关键设计决定（都是实测踩出来的，别轻易改回去）

### 4.1 比例尺决定一切

画布 804px 横向覆盖约 2880km 地面，**1 画布像素 ≈ 3.6km**，属**大陆级小比例尺**。因此：

- 等高距必须**分级**且偏粗。统一 200m 在台湾中央山脉（坡度约 2°）上，
  相邻线地面间距仅 `200/tan(2°) ≈ 5.7km ≈ 1.6px`，会连成一片灰。
- 小比例尺地形图主要靠**晕渲 + 分层设色**表达地形，等高线只是补充。
- 当前分级：`<1500m: 1000m(计曲线)`、`1500–3000m: 500m(一般线)`、`>3000m: 1000m(计曲线)`。

### 4.2 等高线按比例尺渐进显示

CSS `.map-canvas:not([data-lod="0"]) .terr-contours path.is-normal { display: none }`
—— 缩小到只显示计曲线（每 1000m），放大后才放出一般等高线。

依据是制图学的「图上要素随比例尺增减」。固定全显等于把大比例尺的图上内容
套到小比例尺上，实测会把整片丘陵糊成白雾。

### 4.3 位图只画陆地，海面透明

`render_rgb()` 返回 `(rgb, land_mask)`，海面 `alpha=0`。

原因：项目约定「海面用容器底色，不用图层矩形」（海岸线数据覆盖 45°E—239°E，
比画布大得多，任何固定矩形都铺不满）。位图若自带海色，就会在 DEM 覆盖边界
留下一条硬分界线 —— 而视野现在被夹在 DEM 范围内（见第六节），
这条界线本来就不该存在。alpha 还做了 1 格羽化，避免海岸锯齿。

### 4.4 SVG `<image>` 的 x/y 不能为负

本项目 DEM 的 `pad[0]=-348 / pad[1]=-548`，直接写进 `<image>` 会让元素**整体失效**
（请求发出、返回 200，但元素永远不渲染）。必须把负偏移挪到外层 `<g>` 的 translate：

```js
'<g transform="translate(-348 -548)"><image x="0" y="0" .../></g>'
```

### 4.5 按需加载，不进 index.html

`geo-wterrain.js` 约 1.2MB（等高线二十万点），同步 `<script>` 会拖慢首屏。
改为地图渲染后调 `ui.ensureTerrain(canvas)`：先输出一个**空的地形图层占位**，
再在背后注入脚本，加载完**原地 replaceWith 地形图层**——
不整张重建地图，否则用户的缩放/平移与图层勾选态都会丢。

> 2026-10-18 三合一之后地形是**常显**图层（不再有「切到地形图」这个动作），
> 所以触发点从"用户点底图按钮"改成了"每次地图渲染后自动调 ensureTerrain"。
> 沙盘拖滑杆会反复重建地图面板，`ensureTerrain` 因此是幂等的，
> 且回调里**重新查 DOM**（`document.querySelectorAll('.map-canvas')`）而不是捕获入参——
> 只认第一次那个节点的话，第二次重建的地图会永远没有地形。

加载中 / 失败都有对应提示（`.map-canvas[data-terrain=loading|error]::after`），
不能静默——否则用户会看到一张没有起伏的纯绿陆地，又以为"地形没生效"。

### 4.6 坐标必须与 proj() 同源

等高线、高程点、`pad` 全部是**画布像素坐标**，与 `ui.js` 的 `proj()` 同源，
因此地形层与海岸线层、经纬网共用同一个 `.map-view-g` 视野变换，缩放平移不会错位。

> **改投影参数不必重跑 `gen-terrain.py`。** 数据文件里的坐标是在旧投影
> （`x = 351 + (lon−118.0894)×26.79`）下生成的，而两个等距圆柱投影之间只差
> 一个缩放 + 平移，`ui.js` 用 `LEGACY_XF` 把整层包一个 `<g transform>` 就完成了换算。
> 重跑 `gen-terrain.py` 要先重新抓 1.2GB DEM（约 9 分钟），只有改了
> **数据范围**（`fetch-dem.py` 的 bbox）或**配色/等高距**时才需要。

### 4.7 压缩

- 等高线用**相对增量编码**（`M123 456l4 -3`），比绝对坐标省三分之一以上。
- 高程点阈值 2500m、最小间距 150px（实测 1500m/62px 会打出 104 个点，密到互相压字）。

## 五、颜色同步（改一处必须改两处）

`gen-terrain.py` 的 `HYPSO` 与 `css/tokens.css` 的 `--hyps-0..4` 必须一一对应，
图例色带直接引用它们。色标是**按暗色 UI 压暗过的**（标准地形图色表在暗底上偏亮偏黄，
会压过台风路径线）。

## 六、已知取舍

- DEM 只覆盖 92°E—178°E / 4°N—52°N。范围外的陆地由海岸线图层的
  `--map-land` 填充兜底（所以陆地填充层与地形层是**两层叠加**，
  陆地填充不是 `fill:none`；而海岸线描边层 `.map-coast` 才是 `fill:none`）。
- **这条覆盖范围现在就是地图的可平移边界**（`ui.js` 的 `BOUND` / `clampPan()`）。
  原因很直接：一旦视野离开 DEM，画面里就会出现一条笔直的「地形到此为止」的
  直角分界 —— 一侧有晕渲与分层设色，另一侧只剩一层平涂底色，割裂感极强
  （2026-10-18 实测：拖到 92°E / 52°N 就出现）。因此视野被夹在框内，
  缩放下限也定在 100%（再缩小就等于离开数据）。细节见
  `docs/frontend-style-guide.md` §4.13.1。
- 夹住之后唯一还会露出的"无地形"区域是 **178°E—180°E 的远洋**（画布右缘那 20px）。
  那个纬度带里全是开阔洋面，位图海面本就 `alpha=0`，两侧显示同一个容器底色 +
  同一层云，视觉上无从分辨。**若要彻底消除，只能重抓 DEM 到 180°E 再重跑
  `tools/gen-terrain.py`（约要多抓 2% 的瓦片），收益不抵成本。**
- 位图 3MB / 矢量 1.2MB。可接受，但若要再降只能牺牲分辨率或等高线密度。
- 云系是**程序合成的示意云系**（`feTurbulence` + 确定性云团），不是卫星反演产品，
  图例里如实写「云系示意（非观测产品）」。三合一后云常显，
  浓度（`.cloud-tex` 的 opacity）必须压到 0.18 左右，否则会把地形晕渲糊掉。

## 七、回归

`tools/probe-terrain-map.cjs`（32 项）覆盖：空占位 + 按需加载自动触发、
三图层同屏（陆地/地形/云/海岸线）、底图切换按钮确已删除、位图尺寸与 pad 一致、
等高线分级与 LOD 渐进、隐藏地形层前后截图不同（证明地形真的改变画面）、
缩放后线宽不变、地形层与陆地共用同一变换、控制台零错误。
